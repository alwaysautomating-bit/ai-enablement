# Schema

## Tables

- `Organization`: tenant boundary for users, workspaces, and audit events.
- `User`: people who create and approve work.
- `Membership`: organization role and maximum workspace tier.
- `Workspace`: tiered product workspace, currently the L0 Research Assistant.
- `Framework`: stable workflow identity.
- `FrameworkVersion`: immutable input, output, review, and privacy contracts.
- `Run`: one governed execution with question, audience, priority, and status.
- `RunRevision`: immutable generated or revised deliverable content.
- `RunSource`: the exact information selection used by a run.
- `ReviewItem`: blocking human checks attached to one revision.
- `Approval`: human approval attached to one exact revision.
- `AuditEvent`: append-only material workflow events.
- `_AppMigration`: locally applied SQL migration versions.

### Context Capture (CX-04, CX-05, CX-06)

Connections (separate from the context model):

- `SourceGrant`: one user's read-only connection to one provider account (`accessMode` is
  always `READ` at L0).
- `ConnectorCredential`: encrypted OAuth tokens for a grant; empty until live connectors.
- `ClientAccessToken`: hashed personal token for an AI client (Codex, Claude) with scopes.

Context model:

- `Capture`: one bounded investigation — question, window, status machine, extractor
  version and model, stats.
- `CaptureScope`: the exact places a capture may read.
- `Evidence`: pointer to one source message — ids, thread, container, author, recipients,
  `communicatedAt`, permalink, normalized excerpt, content hash, access envelope, source
  ACL description, retention date.
- `Conversation`: a reconstructed conversation within a capture, with the reasons threads
  were linked.
- `CaptureEvidence`: which evidence a capture read, its conversation, duplicate and quote
  links, and whether it was cited.
- `SourceIdentity`: a person as a source system knows them, linked to an entity by
  identity key.
- `OpEntity` / `EntityAlias`: resolved entities (candidate, confirmed, merged) and their
  names.
- `Assertion`: candidate context — kind, bucket, statement, predicate, one-holder flag,
  operational status, modality, confidence, operational time and its basis, communication
  times, derived envelope, review status.
- `AssertionEvidence`: verified quote and offsets supporting, contradicting, or giving
  context to an assertion.
- `ReviewDecision`: an immutable human decision (confirm, correct, not useful) and the
  chosen sharing.
- `OperationalFact`: a reviewed assertion — immutable, with sharing and supersession.
- `Relationship`: a temporal edge between entities with `validFrom` / `validTo`, basis,
  corroborating facts, closure link, envelope, and sharing.

## Purpose

The first schema supports the complete L0 Research Assistant contract: durable inputs,
source provenance, deterministic first-pass and improved revisions, mandatory review,
revision-specific approval, approval invalidation, and audit history.

## Relationships

- An organization has memberships, workspaces, and audit events.
- A workspace owns frameworks and runs.
- A framework has immutable versions; every run records the version it executed.
- A run owns sources, revisions, approvals, and audit events.
- Review items belong to a revision, never only to the run.
- Approvals reference the run, exact revision, and approving user.

## Indexes

- Unique user email and organization/user membership.
- Unique framework/version, run/revision version, and run/source key.
- Run lookup by workspace or creator and creation time.
- Review lookup by revision and acknowledgement state.
- Active approval lookup by run and status.
- Audit lookup by organization or run and creation time.
