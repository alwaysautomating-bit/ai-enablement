# Posterior Update Engine (PyMC Workflow)

## Purpose

This skill defines the technical standards for writing, optimizing, and executing Bayesian inference models inside a production pipeline using **PyMC**. It ensures that all probabilistic calculations are mathematically sound, computationally optimized, and diagnostically robust.

The goal is to maintain absolute execution integrity in our inference systems, preventing sampler failures, divergences, or uncalibrated results.

---

# Model Design & Coding Standards

To ensure stable convergence, all probabilistic models must be built using the following structural standards:

## 1. Non-Centered Reparameterization
For hierarchical parameters (e.g., vendor-level or client-level offsets), always use **non-centered parameterization**. Centered models create high-curvature target distributions (Neal's Funnel) which lead to extensive sampler divergences.

```python
# =====================================================================
# Centered Model (Avoid)
# =====================================================================
# a_vendor = pm.Normal("a_vendor", mu=mu_a, sigma=sigma_a, shape=num_vendors)

# =====================================================================
# Non-Centered Model (Prefer)
# =====================================================================
a_vendor_offset = pm.Normal("a_vendor_offset", mu=0, sigma=1, shape=num_vendors)
a_vendor = pm.Deterministic("a_vendor", mu_a + a_vendor_offset * sigma_a)
```

## 2. Explicit Grounded Priors
Priors must be informed by physical or financial domain boundaries. Do not hardcode magic numbers (unjustified, high-precision values) or default to extremely wide flat priors that make the model un-identifiable.
- Ground log-amount ranges in historical master databases (e.g., standard family office transaction sizes).
- Use lognormal or half-normal distributions to enforce positivity constraints on variance parameters ($\sigma$).

# Execution Pipeline

Every inference run must execute the following sequential pipeline:

```
[ Model Definition ]
        │
        ▼
[ Prior Predictive Check ] ── (Validate range covers domain limits)
        │
        ▼
[ Sample Posterior ] ──────── (nuts_sampler="nutpie")
        │
        ▼
[ Compute Log-Likelihood ] ── (Explicitly call pm.compute_log_likelihood)
        │
        ▼
[ NetCDF Serialization ] ──── (Immediate write via idata.to_netcdf)
        │
        ▼
[ Convergence Diagnostics ] ─ (R-hat, Divergences, ESS check)
```

## 1. Prior Predictive Checks
Before initiating sampling, run a prior predictive check to ensure the prior ranges are physically plausible:
```python
with model:
    prior_idata = pm.sample_prior_predictive(samples=500)
```

## 2. Sampling with Rust-based `nutpie`
Use `nuts_sampler="nutpie"` to speed up the No-U-Turn Sampler by 2–5x. Ensure that random seed and target acceptance rates are defined:
```python
with model:
    idata = pm.sample(
        draws=2000,
        tune=1000,
        target_accept=0.90,
        nuts_sampler="nutpie",
        random_seed=42
    )
```

## 3. Post-Sample Log-Likelihood
Because `nutpie` does not compile log-likelihood vectors by default, you must explicitly compute it after sampling to enable Leave-One-Out (LOO) cross-validation:
```python
with model:
    pm.compute_log_likelihood(idata)
```

## 4. Immediate Serialization
To prevent memory leaks or system crashes from losing computed results, serialize the posterior `InferenceData` object to NetCDF immediately after sampling is complete:
```python
idata.to_netcdf("results.nc")
```

# Convergence & Performance Diagnostics

A posterior update is considered **invalid** if it fails any of the following standard MCMC diagnostic criteria:

### 1. R-hat ($\hat{R}$)
The Gelman-Rubin convergence diagnostic measures variance ratio between chains.
- **Threshold**: $\hat{R} \le 1.00$ (or $< 1.01$) across all variables.
- *Action on failure*: Increase tuning steps (`tune=2000`) or reparameterize.

### 2. Divergences
Divergent transitions indicate the sampler encountered regions of extreme curvature it could not explore.
- **Threshold**: Must be exactly $0$ in production.
- *Action on failure*: Increase `target_accept` (e.g., to `0.95` or `0.99`) or apply non-centered reparameterization.

### 3. Effective Sample Size (ESS)
Measures the number of independent samples generated by the chain.
- **Threshold**: Bulk and tail ESS must be $> 1000$ (minimum absolute limit $> 400$).
- *Action on failure*: Increase draws, improve prior regularizations, or check for collinearities in predictors.
