## 09-29-2026 — Context Capture Loop (Phases 1–4)

### Session Goals

Prove source evidence → conversation reconstruction → candidate assertion → provenance →
review → confirmed context → temporal relationship → MCP retrieval against a realistic
synthetic corpus before connecting live Gmail and Slack. Keep the model domain-neutral and
source chronology separate from operational chronology.

### Completed

- Added 16 context tables (migration `20260929120000_context_capture`) and fixed the local
  migration runner, which silently skipped every migration after the first.
- Built the domain-neutral core in `src/lib/context/`:
  - access envelopes, and a source adapter contract with read-only fixture adapters
  - conversation reconstruction (quote stripping, duplicates, cross-channel linking with
    recorded reasons)
  - provider-agnostic extraction (OpenAI and Anthropic, structured output), versioned prompt,
    deterministic quote verification
  - entity resolution, a capture service that commits atomically
  - a review service with supersession and one-holder timeline reflow
  - permission-aware projections as the single read path
  - principals and hashed client tokens
- Wrote the synthetic corpus: 11 emails and 22 chat messages with late announcements, a
  similarly named vendor, sarcasm, an abandoned hypothetical, a correction, duplicates, stale
  routing, missing context, and out-of-reach messages. Added gold labels and a recorded
  reference response containing one fabricated quote.
- Built the evaluation harness (`npm run context:eval`): scores extraction, simulates review in
  reverse chronological order, and checks the timeline and MCP retrieval as two users.
- Built the MCP server (`scripts/mcp-server.mts`), token issuance, stdio smoke test, and
  `.mcp.json`; wrote the `context-capture` and `operational-context` skills and
  `docs/CONTEXT_MCP_SETUP.md`.
- Built the review experience at `/context` and linked it from the work menu, with
  plain-language copy, both chronologies on every card, source quotes highlighted in context,
  a sharing choice at confirmation, and entity timelines. Added API routes under
  `/api/context`.

### Decisions

- Build Phases 1–4 before real sign-in behind `Principal` and `SourceAdapter` interfaces.
- Keep communication time and operational time separate everywhere, with a time basis.
- Keep entities concrete; activities go in predicates (from the first live run).
- Use strict envelope intersection; timeline reflow only over the reviewer's own
  relationships.
- Use the recorded extractor only as a test double on sample data.
- Pin `better-sqlite3` to 12.x.

### Problems Found

- Reinstalling dependencies left both `better-sqlite3` copies without native bindings; 13.0.1
  has no Node 24 Windows prebuilt. Fixed by aligning to 12.11.1.
- The first live `gpt-5.5` run scored 40% because it modelled "Turner Construction invoice
  approvals" as its own entity. The content and dates were right. Fixed with a domain-neutral
  modelling rule in the prompt and a scorer that matches on what was found. The second run
  passed every check.
- Strict envelope intersection means the second sample user sees none of the approver history,
  because each fact also cites a narrow email thread. This is correct but limits sharing and
  is logged as a design question.
- Captures run synchronously inside the request (about 95 seconds with a live model).

- `npm run context:eval -- --extractor recorded`: PASS, 14/14 checks.
- `OPENAI_EXTRACTION_MODEL=gpt-5.5 npm run context:eval -- --extractor openai`: PASS, 14/14
  checks — 100% of required items, 27/27 quotes verified, 3/3 operational dates, 0 trap
